# Website design prompt: Jev Field Test

This is the build brief for `site/`. It is written to be pasted into any coding or design session, and it was used for
the build in session 8 (2026-10-19). Data comes from `site/data/*.json` (generated by `scripts/export_site_data.py`);
copy rules and facts come from `docs/JEV-FINDINGS.md`.

---

## 1. What to build

A static, multi-page website named **Jev Field Test** that lets an engineer or a decision maker answer one question:
**"Can I trust Jev (TypeSafe's System One decision model, `jev-1.13.0`) for this decision?"** It publishes an independent
field test: 63 public datasets across 27 domains, about 33,800 requests, plus stress tests (number of options, numbers,
injected text, padding, contradictory instructions, wording, batching). It must show, per domain and per dataset, where
Jev works as-is, where it works with a confidence cut-off or human review, and where it does not work zero-shot, and it
must say plainly what was **not** tested.

Constraints: free hosting on GitHub Pages under a sub-path (`https://<user>.github.io/jev-field-test/`), so **no
backend, no build step required, every URL relative (no leading slash)**. No analytics, no cookies, no third-party
requests (no CDN, no web fonts, no embeds). Works from any static file server.

Credit line on every page footer: "Independent and unofficial. Not affiliated with TypeSafe AI. Run on `jev-1.13.0`,
September 2026."

## 2. Audience and tone

Engineers choosing where to put a fast decision model in a product; managers who want a verdict they can read in a
minute. Plain words, evidence first, no hype, no marketing adjectives. Short sentences. Always show the baseline next to
an accuracy ("98.0% against an 86.7% always-no baseline"). Say "possibly seen in training" where relevant. **No em
dashes or en dashes anywhere** (they read as AI-written); use commas, colons or parentheses. Numbers come from the JSON,
never typed into HTML or JavaScript.

## 3. What the references teach (borrow structure, never identity)

Two reference sites were studied page by page.

- decisionbench.ai (static Vite app, data in JSON files): a leaderboard with accuracy dots and 95% interval whiskers,
  a use-case browse list with text bar charts, a heatmap where only misses are coloured and cells at or above 95%
  fade, "Fits / Risky / Not fit" pills from a stated rule, a "where it fails" list, a reliability diagram and a
  risk-coverage curve ("error rate if low-confidence answers go to a person"), task pages that show the actual
  question and options, a Data page with a licence per dataset, a Downloads block of plain files, a dark-mode toggle,
  a mono display face on an off-white grid, one blue accent.
- The Jev Decision Index (static Hugging Face Space): radar charts per skill area, Pareto scatter plots, a sortable
  results table, a methodology page with pill sub-navigation, a "Reproduce" section and a changelog.

**Do not copy**: their names, logos, mascot, colours as a set, page copy, or data. Our identity is its own: a quiet
instrument-panel look (monospace labels, hairline grid, one accent, three verdict colours), a small original wordmark
(a 3 by 3 dot grid with one filled dot) and the name "Jev Field Test".

## 4. Information architecture (multi-page, deep-linkable)

| Page | File | Purpose |
|---|---|---|
| Scorecard (home) | `index.html` | Verdict at a glance and entry to everything |
| Domains | `domains.html` | One card per domain: plain verdict, what to do |
| Dataset detail | `dataset.html?id=<id>` | Everything about one dataset |
| Failure modes | `failure-modes.html` | TypeSafe's nine documented weak spots against what we measured |
| Stress tests | `stress-tests.html` | Option scaling, numbers, decomposition, none-option, batching, order, phrasing, reproducibility |
| Trust and confidence | `trust.html` | Calibration, confident-wrong rates, cut-offs, recalibration |
| Method and limits | `method.html` | Test catalogue, rules, caveats, open questions, reproduce, downloads, sources, licences |

Global header: wordmark, six links (Scorecard, Domains, Failure modes, Stress tests, Trust, Method; dataset pages are reached from the table), dark-mode toggle, link to the GitHub repo once `config.json` names it. On phones the header is one compact row with a horizontally scrolling nav row and is not sticky. Footer: credit line, run date,
link to Method. A skip link, landmark roles and one `<h1>` per page.

### 4.1 Scorecard (`index.html`)
1. Hero: eyebrow "FIELD TEST · jev-1.13.0 · SEPTEMBER 2026", H1 "Can Jev make this decision for you?", two sentences of
   context, and a stat strip (`meta.json`): datasets, domains, requests answered, API cost, median latency.
2. Verdict split: three big counts (A works as-is, B works with a cut-off or review, C not usable zero-shot) with the
   rule in one line each (`meta.verdict_words`), each count linking to the filtered table below.
3. Domain browse list: 27 rows with a text bar of A, B, C counts (monospace block characters), name, mean accuracy;
   click filters the table.
4. "Where Jev is strong" and "Where Jev is weak": two lists of six datasets each with accuracy against baseline,
   chosen by rule (A with the highest accuracy over baseline; C with the lowest accuracy over baseline or the highest
   confident-wrong share), generated, not hand-picked.
5. The nine failure modes as a 3 by 3 grid of cards: name, status chip (Tested, Tested one form, Tested one style,
   Partly, Not tested by design), one line, link to the scorecard page.
6. Dataset table (see 6.1): search, domain filter, verdict filter, task-type filter, sortable columns, row click opens
   the dataset page. Heatmap toggle (see 6.2).

### 4.2 Domains (`domains.html`)
Card per domain (`domains.json`): name, A/B/C dots, mean accuracy against mean baseline, confident-wrong share, the plain
note, the dataset chips (each links to its page). A radar chart for the ten largest domains (mean accuracy), with the
baseline polygon in grey.

### 4.3 Dataset detail (`dataset.html`)
Breadcrumb; title; verdict pill; "what it tests" sentence. Metric tiles: accuracy with interval whiskers and the
baseline tick, ROC-AUC or top-3 or within-one, ECE, wrong at 0.9 or more (share of all). "The question Jev saw" panel
(`framing`: instruction and options, first 12 options with a "+N more" note). Reliability diagram and risk-coverage
curve (`calibration.json`). Cut-off box: the recommended cut-off, share automated, held-out wrong rate, guaranteed
cut-off if any, and a sentence in plain words. Slices table where it exists (`slices.json`). Flags (possibly seen in
training, too few answers, items skipped for context). Source and licence line.

### 4.4 Failure modes (`failure-modes.html`)
Nine sections from `failure_modes.json`: number, name, status chip, evidence bullets (generated strings), "reading" line.
Each links to the chart or table that backs it on the stress-test page. A closing "not tested" box (`open_questions`).

### 4.5 Stress tests (`stress-tests.html`)
- Number of options: one small line chart per dataset (accuracy against 4, 6, 16, 32, 64 options, chance line, the
  full-label-set mark as a hollow dot).
- Numbers: ULB balanced control (50.0% against chance), CVSS numeric against worded (paired bars, McNemar p), BBH
  counting against the other sub-tasks.
- Failure-mode probes: a table (conditions by dataset: accuracy, lost, gained, p) and the P(q) + P(not q) statistics.
- Decomposition: single question against six narrow questions plus combiner, with the combiner weights.
- None-of-these option, batching, option order and key names, question against statement wording, reproducibility
  across days: compact paired tables.

### 4.6 Trust and confidence (`trust.html`)
Pooled reliability diagram; confident-wrong share per domain (bars, sorted); the table of recommended cut-offs per
dataset (cut-off, automated share, held-out wrong, guaranteed cut-off) sortable and filterable; recalibration summary
(raw against recalibrated ECE per dataset, as paired dots); the human-disagreement comparison. A "how to pick a
threshold" box in four sentences.

### 4.7 Method and limits (`method.html`)
Pill sub-navigation (sticky on the shorter pages, static on this one) with anchors: Test catalogue, How a result is scored, Verdict rules, Limits, Open questions,
Reproduce, Downloads, Datasets and licences, Changelog. Content from `meta.tests`, `meta.anchors`,
`meta.open_questions`, plus short written sections.

## 5. Data contract (all files in `data/`, fetched with relative URLs)

`meta.json` (counts, cost, latency, verdict words and rules, tests, anchors, open questions) ·
`datasets.json` (63 rows: id, title, domain, verdict, accuracy, ci95, baseline, top2, top3, within_1, roc_auc, ece,
brier, auroc_confidence, confident_90, wrong_among_confident_90, correct_with_conf_70, wrong_all_90/70/50, cutoff,
cutoff_automated, cutoff_heldout_wrong, guaranteed_cutoff, ece_recalibrated, latency_p50_ms, flags, framing, license,
what_it_tests, n_options, question_types, answers, records) · `domains.json` · `slices.json` · `calibration.json`
(per dataset `reliability[]`, `coverage[]`; `_all` pooled) · `experiments.json` · `failure_modes.json`.
Percent values are fractions (0.97 means 97%). Never recompute metrics in the browser except sorting, filtering,
intervals for display and the heatmap bucketing.

## 6. Components and interactions

### 6.1 Dataset table
Columns: Verdict pill, Dataset (title, domain chip), Accuracy (number plus dot-and-whisker on a 0 to 100 axis with a
baseline tick), Baseline, Wrong at 0.9+ (share of all), Cut-off (value or "none"), Answers. Click a header to sort
(aria-sort), type in the search box to filter on title, id, domain, what-it-tests; filters sync to the URL query so a
filtered view can be shared. Row is a link to the dataset page. Sticky header; horizontal scroll on narrow screens with
the first column pinned.

### 6.2 Heatmap
Domains (rows) by verdict (columns A, B, C) or datasets by metric; colour only where the result is a miss
(C, or accuracy below baseline), fade cells that are A; every cell also carries its number so colour is never the only
carrier.

### 6.3 Charts (inline SVG written by a small `charts.js`, no library)
Accuracy dot with Wilson-style interval whisker (use the stored `ci95`); baseline tick; chance line; reliability
diagram (diagonal reference, point area proportional to n, hide bins under 10 answers); risk-coverage curve (x: share of
answers automated from most confident, y: error rate among those); line chart for option scaling; paired bars for
two conditions; radar. Every chart has a text alternative (a visually hidden table or `aria-label` with the key
numbers), tooltips on hover and on keyboard focus, no animation beyond a 150 ms fade, and `prefers-reduced-motion`
turns even that off.

### 6.4 Pills and chips
Verdict pill: shape plus text plus colour (A filled circle "Works as-is", B triangle "Cut-off or review", C square
"Not usable"). Status chip for failure modes: text only with a thin border. Flags are plain text chips.

### 6.5 Theme
Light and dark, following `prefers-color-scheme` with a manual toggle saved in `localStorage` (wrapped in try/catch;
works without it). The toggle sets `data-theme` on `<html>`.

## 7. Visual system

**Principles**: an instrument panel, not a landing page. Quiet surface, hairlines, tabular figures, one accent, three
verdict colours that survive colour-blindness and greyscale, generous whitespace, nothing decorative.

**Type** (system fonts only, no downloads): display and labels `ui-monospace, "SF Mono", Menlo, Consolas, monospace`;
body `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`. Scale (rem): 0.75 label (uppercase, 0.08em tracking),
0.875 small, 1 body, 1.125 lead, 1.5, 2, 3.25 hero (mono, tight line height 1.05). Numbers use
`font-variant-numeric: tabular-nums`. Body line length 65 to 72 characters.

**Tokens** (define on `:root`, override under `@media (prefers-color-scheme: dark)` guarded by
`:root:not([data-theme="light"])` and again for `:root[data-theme="dark"]`; give `body` an explicit background):

| Token | Light | Dark |
|---|---|---|
| `--bg` | `#f7f6f2` | `#121110` |
| `--surface` | `#ffffff` | `#1a1917` |
| `--ink` | `#14130f` | `#ece9e1` |
| `--muted` | `#5c5a52` | `#a39f94` |
| `--line` | `#d9d6cc` | `#33312c` |
| `--grid` | `rgba(20,19,15,.05)` | `rgba(236,233,225,.06)` |
| `--accent` | `#2636d8` | `#8f9bff` |
| `--ok` (A) | `#0b6b5f` | `#4cd1bd` |
| `--mid` (B) | `#a24d00` | `#f2a54d` |
| `--bad` (C) | `#b3261e` | `#ff8374` |

Check every text and chart colour for WCAG AA against its background in both themes (4.5:1 for text, 3:1 for graphics).
Page background has a faint 24 px grid made with `background-image` (two linear gradients) that fades out below the
hero. Radius 6 px, borders 1 px `--line`, no shadows except a 1 px focus ring in `--accent` (2 px offset).

**Layout**: max content width 1120 px, 16 px side gutters up to 640 px, 24 px above; 12-column CSS grid, 8 px spacing
unit. Header 56 px, sticky. Cards are flat. Tables use hairline row separators, 44 px row height, right-aligned numbers.

**Responsive**: designed at 375, 768 and 1280 px. At phone width the stat strip becomes 2 by 3, the failure-mode grid and
domain cards become one column, tables scroll horizontally with a pinned first column, charts keep a minimum width of
320 px and scroll rather than shrink illegibly. No horizontal page scroll.

**Accessibility**: semantic landmarks, one `h1`, logical heading order, visible focus, 44 px touch targets, `aria-sort`
on sortable headers, charts with text alternatives, colour never the only carrier, `lang="en"`, reduced-motion
respected, content readable at 200% zoom, keyboard-only path through filters, table and chart tooltips.

**Performance and structure**: under 300 KB of JavaScript and CSS together (gzip) excluding data; ES modules
(`type="module"`), no framework, no CDN. Files: `css/site.css`, `js/app.js` (shared), `js/charts.js`, one small module per
page, `data/*.json`, `assets/` (favicon SVG, social image). Every `fetch` and `src` is relative. Add `<noscript>` text that
says the pages need JavaScript to draw tables and charts and links the JSON files. `<meta name="description">`, Open Graph
and Twitter tags with a generated social card (`assets/og.png`, 1200 by 630).

## 8. Copy rules

- Headline claims: "Jev works as-is on 11 of 63 datasets" style, always with the denominator, and the number comes from
  `meta.verdicts`.
- Always pair accuracy with its baseline; never say "high accuracy" without a number.
- Say "possibly seen in training" for MMLU-Pro, MedMCQA, BoolQ, SST-2, BBH, QuALITY.
- Say "not tested" when it was not tested. Never say "Jev is safe from X".
- Dataset names as published; do not quote or reproduce dataset text. Our own question wording may be shown.
- Independent and unofficial line on every page. No logo of TypeSafe, Hugging Face or any vendor.

## 9. Acceptance checklist

1. Opens from a static server at `/` and at `/jev-field-test/` (sub-path) with no broken links, images or fetches.
2. All seven pages render at 375, 768 and 1280 px, light and dark, with no horizontal page scroll and no console errors.
3. Every number on a page equals the JSON; ten datasets and all nine failure modes spot-checked against
   `docs/RESULTS.md`.
4. Keyboard: tab order is logical, filters and sort work without a mouse, focus is visible, skip link works.
5. Contrast: text 4.5:1 and graphics 3:1 in both themes; verdict pills readable in greyscale.
6. No request leaves the origin (check the network list); no cookies; only `localStorage` for the theme.
7. No em or en dashes in any rendered text (`grep` the pages and the JSON).
8. Size: JS and CSS under 300 KB gzip; the whole site a few MB at most.
